# Initial Configuration

Virexa is powered by a FastAPI backend and a Discord bot. This page covers the minimal setup required to get the dashboard online, connect your Discord server, and enable the core moderation and logging features.

:::tip
**Recommendation:** Complete these steps immediately after deploying or starting Virexa so that logs, moderation events, and configuration are captured correctly from day one.
:::

---

## 1. Configure Environment & OAuth

Before running the FastAPI app in production, ensure the following environment variables (or settings) are configured:

- `DISCORD_CLIENT_ID`  
- `DISCORD_CLIENT_SECRET`  
- `DISCORD_REDIRECT_URI`

These values are used by the `/auth/discord/url` and `/auth/callback` endpoints to perform Discord OAuth2 authentication.

:::note
The `DISCORD_REDIRECT_URI` must exactly match the callback URL registered in your Discord application settings (for example, `https://your-domain.com/auth/callback`).
:::

---

## 2. Run the FastAPI Application

In development, you can typically start Virexa using `uvicorn`:

```bash
uvicorn dashboard.main:app --reload --port 8000
```

Once running, the dashboard and API are exposed at:

- **Dashboard UI:** `GET /`  
- **Interactive API docs (for developers):** `GET /api/docs` and `GET /api/redoc`  
- **Static docs (this site, when deployed separately):** served by your Nuxt/Content frontend

---

## 3. Invite the Virexa Bot

Invite the bot to your Discord server using your deployment’s invite URL.

:::tip
You must have the **Manage Server** permission in the target guild to add the bot.
:::

Once invited, confirm that:

- The bot appears online.  
- The bot’s role is positioned high enough in the role hierarchy to perform moderation and role changes (see [Permissions](/en/getting-started/permissions)).

---

## 4. Log In to the Dashboard

1. Open your dashboard URL (for example, `http://localhost:8000`).  
2. Click **Login with Discord**.  
3. Complete the Discord OAuth2 flow.  
4. After successful login, Virexa:
   - Creates or updates the user record in the database.  
   - Stores a session cookie on your browser.  
   - Makes the `/api/me` and `/api/guilds` endpoints available for your session.

From here, you can select one of your administrator guilds and start configuring that server.

---

## 5. Basic Server Configuration

Once a server is selected, use the dashboard (backed by `POST /settings`) to configure core options:

### Prefix & Command Behavior

- Set a **custom prefix** for any text-based commands your bot supports.  
- Keep it short and unambiguous (for example: `!`, `.`, `?`, `>>`).

### Logging Channel

- Choose a dedicated **log channel ID** where events will be sent.  
- Ensure the bot has permission to **View Channel**, **Send Messages**, and **Embed Links** in that channel.

### Event Subscriptions

Virexa stores a list of events per guild (via the `Event` model). When you save the settings form:

- Existing events are toggled on/off.  
- Newly enabled events are created if they do not exist yet.  
- Only selected events will be processed and sent to logs or the dashboard.

---

## 6. Real-Time Logs & Monitoring

The dashboard uses two main mechanisms for logs:

- `GET /api/logs` — Fetches the latest batch of logs for tables or initial page loads.  
- `WEBSOCKET /ws/logs` — Streams new logs every few seconds to connected clients.

Once you’ve configured logging and started generating activity in your Discord server, open the logs view in the dashboard to confirm:

- Recent events appear shortly after they happen.  
- New logs stream in automatically without refreshing the page.

---

## 7. Quick Checklist

- [ ] Environment variables (`DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_REDIRECT_URI`) set correctly  
- [ ] FastAPI app running and reachable by staff  
- [ ] Bot invited to target servers  
- [ ] Bot role placed correctly in the Discord role hierarchy  
- [ ] Dashboard login via Discord working  
- [ ] Prefix, log channel, and events configured via **Settings**  
- [ ] Logs visible on the dashboard and streaming via WebSocket

---

:::note
If something isn’t working as expected, review [Permissions](/en/getting-started/permissions) first—most issues come from missing Discord permissions or incorrect role hierarchy.
:::
