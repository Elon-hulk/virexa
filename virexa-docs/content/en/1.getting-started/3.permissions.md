Virexa relies on correct **Discord permissions** and **role hierarchy** to perform moderation, logging, backups, and automation safely.

Most setup problems trace back to:

- The bot’s role being too low in the hierarchy  
- Missing critical permissions (for example, **Manage Roles** or **Read Message History**)

---

## Role Hierarchy

:::caution
Place Virexa’s bot role **above** any roles it needs to manage (muted roles, auto-roles, staff roles) and **below** your highest administrative roles.
:::

If the bot’s role is lower than a target role, Virexa **cannot**:

- Assign or remove that role  
- Mute or unmute members holding that role  
- Apply some moderation actions to those users

Always verify the role order in **Server Settings → Roles** after inviting the bot.

---

## Required Permissions

### Core Permissions

These are required for Virexa to operate as intended:

| Permission | Why It’s Needed |
|-----------|-----------------|
| **Manage Server** | Used for backup/restore workflows and certain configuration tasks. |
| **Manage Roles** | Required for role management, mutes, and automated role assignment. |
| **Manage Channels** | Needed for purge operations, log channels, and some structural changes. |
| **Kick Members** / **Ban Members** | Required for moderation actions such as kicks and bans. |
| **Read Message History** | Allows the bot to inspect past messages for logging and purge filters. |
| **Manage Messages** | Needed to delete messages during purge operations. |

If you disable any of these, expect corresponding features to fail or degrade.

---

## Channel-Level Overrides

Even if the server-wide permissions look correct, per-channel overrides can block Virexa.

For each channel where Virexa should act (logs, moderation, general use), make sure the bot can:

- **View Channel**  
- **Send Messages**  
- **Embed Links**  
- **Read Message History** (for purge and logging)

For log channels specifically, double-check that no deny overrides are preventing messages from being written.

---

## API & Dashboard Access

The FastAPI application enforces access at the application layer:

- `/api/me` and `/api/guilds` require a valid session cookie established via Discord OAuth.  
- Dashboard pages that rely on guild data assume the user is an administrator in the corresponding server.

If a user:

- Is not authenticated → Virexa returns `401` or redirects to login.  
- Is authenticated but not an admin in a guild → That guild will not appear in `/api/guilds`, and they cannot configure it through the dashboard.

---

## Checklist

- [ ] Virexa bot role is above managed roles (muted/auto/staff roles)  
- [ ] Required permissions are granted at the server level  
- [ ] Channel overrides allow the bot to view, send, and read where necessary  
- [ ] Staff using the dashboard are server admins for the guilds they manage  

:::note
If moderation actions or role changes silently fail, check role hierarchy **first**, then confirm the specific permission on the affected channel.
:::
